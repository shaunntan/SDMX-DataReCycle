# Data Re-cycle — minimum app bundle

This folder is the minimum set of files needed to run the "Data Re-cycle"
webapp as a fresh repository:

- `web/` — the Next.js frontend + API routes (the UI you interact with)
- `PrototypeCodes/` — the Python backend the webapp shells out to for the
  real report-to-SDMX pipeline (uploads, AI review, export suggestions,
  export validation)
- `ArtifactPrinciples/` — artifact-definition reference text the pipeline
  reads on every run; required, not optional (see below)
- `PROMPTS.md` — log of prompts given to Claude during development
- `ArtifactScripts/` — not required to run the app; kept for provenance.
  These are the scripts used during vibecoding of the app (the CLI-era
  pipeline runner and its dev/test utilities) rather than dependencies of
  the webapp itself. See **`ArtifactScripts/`** below.
- `ArtifactJSON/` — not required to run the app; kept for provenance. These
  sample per-artifact-type JSON/CSV outputs were used as references for
  Claude Code and Codex while vibecoding the app, not consumed by the
  webapp or backend scripts at runtime. See **`ArtifactJSON/`** below.

Everything else from the original project (build output, `node_modules`,
the Python virtualenv, downloaded ML model cache, and the pipeline's
generated data folders) was deliberately left out — see **What's excluded**
below.

## Prerequisites

- Node.js 20+ and npm
- Python 3.12
- A working `codex` CLI on your `PATH` (or set `SDMX_CODEX_BIN` to its path),
  authenticated for your account. The backend's AI-review, export-suggestion,
  and manual-retry scripts shell out to this binary — without it those
  features fail gracefully (the webapp shows a "pipeline environment not
  set up" style message) but the rest of the UI still works.

## Quick setup

```bash
./setup.sh
```

This installs the frontend's `node_modules` and creates
`PrototypeCodes/.venv` with all Python dependencies. It does not start the
app or set up `codex` — see below to run the app, and **Prerequisites**
above for the `codex` CLI. The steps below are what `setup.sh` runs; use
them directly if you'd rather set things up by hand.

## 1. Set up the frontend

```bash
cd web
npm install
npm run dev
```

This starts the app at `http://localhost:3000`. On first run it creates
`web/data/app.db` (SQLite) automatically — no manual DB setup needed.

## 2. Set up the Python backend

The frontend expects a virtualenv at `PrototypeCodes/.venv` with the
interpreter at `PrototypeCodes/.venv/bin/python3`. Create it:

```bash
cd PrototypeCodes
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Nothing else to configure — `run_web_job.py`, `run_manual_retry.py`,
`ai_review.py`, `export_suggest.py`, and `validate_export.py` are invoked
directly by the webapp's API routes with `cwd=PrototypeCodes/`. Under the
hood, `run_web_job.py` and `run_manual_retry.py` both also import and call
into `run_pipeline.py`, so that script (included here) is a real runtime
dependency of the upload flow, not a standalone CLI you can skip.

The embedding model (`bge-base-en-v1.5-onnx-q`) used for report chunking is
downloaded automatically into `PrototypeCodes/model_cache/` on first use —
no manual download step.

`run_pipeline.py` also requires `ArtifactPrinciples/` (copied alongside
`PrototypeCodes/` and `web/` at the repo root — keep it a sibling of
`PrototypeCodes/`, matching the layout `pipeline/config.py` expects) to be
present and populated. Without it, every upload job fails immediately —
see **Note: why `ArtifactPrinciples/` is included** below for why this one
can't be auto-generated like the DB or model cache.

## 3. Use the app

With both `npm run dev` (in `web/`) and the `.venv` set up, open
`http://localhost:3000` and upload a report. The webapp will spawn the
Python pipeline in the background and poll its status.

## What's excluded (and why you don't need it)

| Excluded | Why |
|---|---|
| `web/node_modules/`, `web/.next/` | Regenerated by `npm install` / `npm run dev` / `npm run build` |
| `web/next-env.d.ts`, `web/tsconfig.tsbuildinfo` | Auto-regenerated by Next.js/TypeScript on first run |
| `web/data/app.db*`, `web/data/jobs/` | Runtime state — `src/lib/db.ts` creates and migrates the DB schema itself on first request |
| `PrototypeCodes/.venv/` | Recreate with the commands in step 2 |
| `PrototypeCodes/model_cache/` (~200MB) | Auto-downloaded by `fastembed` on first embedding call |
| `PrototypeCodes/create_10_synthetic_examples.py`, `create_synthetic_pdf.py`, `verify_pipeline.py` | Dev/test CLI utilities — never imported or called by the webapp |
| `pipeline_control.xlsx` | Auto-created by `pipeline/control.py`'s `ControlWorkbook` (`openpyxl.Workbook()`) the first time it's missing — no need to supply it |
| Root-level Python dataset generator (`generate_dataset.py`, `reload_dataset.py`) and SDMX/artifact folders | Separate tooling unrelated to the webapp |

## `ArtifactScripts/`

The files in `ArtifactScripts/` were used in the process of vibecoding the
app — they are not part of the running webapp and are not required by
`setup.sh` or any step above. They're included for provenance/reference
only (e.g. to see how the pipeline was originally driven from the CLI
before the Next.js frontend existed). Safe to delete if you don't need the
history.

## `ArtifactJSON/`

The files in `ArtifactJSON/` (per-artifact-type example JSON/CSV, one set
per artifact — Concept Scheme, Codelists, DSD Key Family, Dataflow,
Metadata Set, Metadata Structure Definition MSD, AI Fillable Data
Template, Codebook and Source Mapping) were used as references for Claude
Code and Codex when vibecoding the app. Nothing in `web/` or
`PrototypeCodes/` reads from this folder at runtime — it's included for
provenance/reference only. Safe to delete if you don't need the history.

## Note: why `ArtifactPrinciples/` is included

`PrototypeCodes/pipeline/config.py` resolves several inputs as siblings of
the repo's `PrototypeCodes/` folder (`ArtifactPrinciples/`, plus various
`Inputs*/`/`Artifact JSON/` working directories). The working directories
are auto-created on first pipeline run (`ensure_directories()`), but
`ArtifactPrinciples/`'s *content* is not auto-generated —
`pipeline/artifacts.py`'s `discover_artifacts()` raises `FileNotFoundError`
if the folder is missing, or `ValueError` if it has no matching `.txt`
files, and this is called unconditionally at the top of
`run_pipeline.main()` (before any `--skip-aggregate`/`--aggregate-only`
branching), which `run_web_job.py` calls for every upload. That's why
`ArtifactPrinciples/` is copied into this bundle rather than left out: it
is a hard requirement of the upload flow, not an optional enhancement.
