COMMON SDMX CONCEPTS AND STANDARD CODE SOURCES
==============================================

Purpose
-------
This is a starting checklist when analysing a report. It is NOT a rule that every
concept belongs in every DSD.

The role shown is typical, not mandatory. The statistical meaning of the source
data determines the final role.

A. CORE / VERY COMMON SDMX FIELDS
---------------------------------
CONCEPT          TYPICAL ROLE     STANDARD / RECOMMENDATION
---------------  ---------------  ------------------------------------------------
REF_AREA         Dimension        Check SDMX CL_AREA, domain area list, UN M49,
                                  ISO 3166. Use the list whose semantics match.
COUNTERPART_AREA Dimension        Often uses an area codelist too, but has a
                                  different semantic role from REF_AREA.
FREQ             Dimension        SDMX CL_FREQ.
TIME_PERIOD      Time dimension   Time representation, not normally a codelist.
OBS_VALUE        Primary measure  Value of measured variable.
OBS_STATUS       Attribute        SDMX CL_OBS_STATUS.
CONF_STATUS      Attribute        SDMX CL_CONF_STATUS.
UNIT_MEASURE     Attr/Dimension   Use authoritative domain unit list. Registry has
                                  unit lists from agencies such as UNSD/Eurostat.
UNIT_MULT        Attribute        SDMX CL_UNIT_MULT.
DECIMALS         Attribute        SDMX CL_DECIMALS.
BREAK_REASON     Attribute        SDMX CL_BREAK_REASON.
SEASONAL_ADJUST  Attr/Dimension   SDMX CL_SEASONAL_ADJUST.
TIME_FORMAT      Attribute        SDMX CL_TIME_FORMAT where relevant.
TIME_PER_COLLECT Attribute        SDMX CL_TIME_PER_COLLECT where relevant.

                 Dimension        Use the sector classification required by the

STATISTICAL_OPERATION

E. GENERIC DOMAIN FIELDS THAT OFTEN REQUIRE LOCAL/DOMAIN SCHEMES
---------------------------------------------------------------
INDICATOR        Dimension        Search existing domain DSD first. New indicator
                                  list may be necessary if report indicators are
                                  genuinely unique.
MEASURE          Dimension        Some domain models use a measure dimension.
STAT_UNIT        Dimension/Attr   Use domain definition/codelist.
SOURCE           Attribute/Meta   Short coded source may be a data attribute;
                                  narrative source belongs in reference metadata.
COMPILING_ORG    Attribute/Meta   SDMX Glossary cross-domain concept.
TITLE            Attribute/Meta   Usually metadata/presentation, not a dimension.
BASE_PERIOD      Attribute/Dim    Domain-specific; verify exact concept definition.
REFERENCE_PERIOD_DETAIL
                 Attr/Dim         Domain-specific, often used for additional
                                  temporal qualification.

--------------------------------------
1. SDMX Global Registry
   https://registry.sdmx.org/items/codelist.html

   Search by concept/codelist ID and inspect:
   - maintenance agency;
   - version;
   - definition;
   - codes;
   - domain usage.

H. REUSE DECISION RULE
----------------------
For every candidate value:
1. What statistical concept does it represent?
2. Which organisation is authoritative for that concept?
3. Does an existing codelist contain a semantically equivalent code?
4. Is its version compatible with the report's methodology/reference period?
5. Does the existing code's scope exactly match?
6. If yes: reuse it.
7. If no: document the gap before creating a local code.

I. IMPORTANT CAUTIONS
---------------------
- A code list can be technically reusable but statistically inappropriate.
- Country code systems differ in purpose and treatment of aggregates/territories.
- Age groupings are highly domain-dependent.
- Unit codes can be domain-specific and can combine scale/denominator concepts.
- Classification revision matters.
- "Total", "Other", "Unknown", "Not applicable" and "Unspecified" must have explicit
  definitions and should never be mapped on label alone.
- Do not confuse missing-data status with a statistical category.
- Do not use OBS_VALUE to carry formatted strings such as "12.4%" if unit is
  separately modelled.
